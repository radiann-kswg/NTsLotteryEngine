# DESIGN.md — NTsLotoEngine 抽選仕様と機構

## 1. コンセプト

ナンバーテールズのコンテンツ用ボール抽選機。**当選は物理が決める**（2026-09-03 User 指示。RNG で先に決めて誘導する旧方式は「作為的」なので廃止）。

- 2〜11・12〜99 は **篩型ロトマシーン**: 穴あきの回転皿を縦に重ね（4 層／15 層）、球は穴を見つけるたびに下へ落ちる。最下層の受け口に**到達した順**が抽選順。
- 別ボール 7 台は **縦連クルーン**: 各段 = 回転ボウル（穴は一様）＋静止コレクタ（当たり扇形は軸へ／ハズレ扇形は外周の樋へ）。当選率はコレクタの当たり扇形の角度比で作り、**モンテカルロ（`Tools > NTsLoto > Monte Carlo`）で実測して有効数字 2 桁を保証**する。
- 抽選機のモデルは **Blender で生成**（`BlenderSources/gen_kuruun.py` + `kuruun_params.json` → `Assets/Models/*.fbx`）。Unity 側（`LotoSceneBuilder`）は配置と配管だけ。RSC と同じ方針。
- 1 台ずつ順番に回し、固定カメラを切り替える（動画向け）。

  **18.5°×2 → p=0.0000・timeout 11%**（当たり扇形に落ちた球が全部内縁で詰まる）、**9.25°×4 → p=0.0000・timeout 0**（球が跨いで入れない）。

- 校正の経緯（旧値との差の原因）: MC 治具の 1 試行目がボウル中心へ落ちる穴（+parallel/trials）・境界角の 3.75° 量子化・ハズレ床の内縁 0.02 越え（AGENTS.md 罠16〜18）。

### 2.2 段ごとの当選率と落下方位（2026-09-04 実測）

**当落を決めているのは「球がコレクタ天端（−0.20）を割った瞬間の方位」**（塔ローカル・Unity 角）。実機 407 段のログで、
この方位が当たり扇形に入っているかどうかから当落を **99.0%（403/407）** 再現できた（残り 4 件は詰まり救済で再投入された球。
方位ログは最初の 1 回しか記録しないので、2 回目の落下と食い違う）。**したがって「落下方位の分布が一様か」が公平性のすべて**。

塔の構造上、**各段の投入方位は固定されている**（喉が段ごとに x=±0.425 交互）:

| 段 | 投入方位（塔ローカル Unity 角） | 由来 |

| 奇数段（1,3,5…） | **270°** | 上段の喉 x=−0.425 → 当段のボウル中心 x=+0.425 |
| 偶数段（2,4,6…） | **90°** | 上段の喉 x=+0.425 → 当段のボウル中心 x=−0.425 |

#### (c) わかったこと

1. **「投入方位が固定だから当落が決まる」ほど極端ではない。** 実機は喉から落ちてくる球の位置・速度・スピンがばらけるので
   Δ の中央値が 105〜115°・分布が広く、治具の方位固定（Δ が +30° に集中）とは別物。段ごとの p の差は概ね 95% CI に収まる
   （p50: 0.477 / 0.583 / 0.607、p53: 0.585 / 0.531 / 0.423）。**MC の「方位固定」欄は実機の予測値としては使えない**。
2. **ただし落下方位は一様ではなく、校正値からズレている。** 120〜150° と 300° に山、0〜90° が谷。結果、
   当たり扇形が **270°** の塔（p10・p6of88・p18）は全部高く（0.169 / 0.123 / 0.261 vs 0.100 / 0.068 / 0.181）、
   **0/180°** の p32 は低い（0.226 vs 0.318）。扇形が広い p50・p53 は方位の山谷を跨ぐので校正値どおり（0.539 / 0.536）。
   p10 は 95% CI [0.117,0.237] が目標 0.100 を外している＝**有効数字 2 桁の保証は現状崩れている**。
3. **p18 の奇数段が高い傾向**（0.533 [0.301,0.752] vs 最上段 0.215）。n=15 なので確定ではないが、段による偏りが残っている可能性。

#### (d) 対策: 当たり扇形を円周に散らした（2026-09-04 実施）

`BlenderSources/kuruun_params.json` の `variants.*.win` を等間隔の複数本に割り、`gen_kuruun.py` で作り直した（2.1 節が新しい校正値）。
扇形が方位分布の山と谷を跨ぐので、偏りが平均される。

**ただし 1 本 21° の下限がある**（内縁 r_in=0.36 で `θ·r_in − 壁厚 0.02` < 球径 0.1 だと楔に挟まる。MC 実測: 18.5°×2 → p=0・timeout 11%／9.25°×4 → p=0・timeout 0）。
結果、**合計角の小さい p10（37°）と p6of88（25.1°）は分割できず 1 本のまま**。

#### (f) 残っている手（p10 / p6of88 用・未着手）

- **コレクタの当たり／ハズレ円盤だけをボウルと違う回転数で回す**（樋は静止のまま分離）。当たり扇形が方位に対して一様になるので、
  本数に関係なく **いまの校正値（＝方位平均）がそのまま正しくなる**（(a) の「12 点平均 ≈ 校正値」が根拠）。`gen_kuruun.py` で円盤と樋を別オブジェクトに分ける必要がある。
- **内縁 r_in を広げる**（0.36 → 0.45 など）と 1 本の下限が 21° → 17° 程度に下がり、p10 を 2 本に割れる。ただし漏斗・落差・全 variant の再校正が要る。
- 扇形の境目の放射壁を内縁の手前（r ≈ 0.46）で止める案もある（詰まりは内縁で起きているため）。当たり床は隣のハズレ床より低いので壁が無くても越えられない見込みだが、未検証。

## 3. 機構（正本: `Assets/Scripts/Editor/LotoSceneBuilder.cs`・寸法は `BlenderSources/kuruun_params.json`）

単位 m。球は LotteryBallKit `NumberBall`（径 0.1 = d）。FBX の角度規約: **Unity 角 = Blender θ + 180°**（レイキャスト実測）。

### 3.1 篩型ロトマシーン ×2（`SieveMachine`）

```
  Spawn（最上層の 0.45 上・螺旋にばらまく。位置と生成順は毎回シャッフル: 番号順だと最後に生成した球が 6 回連続で最初に着いた）
 ╲______╱  Dish 0  … 回転皿（Sieve_Dish_L: φ1.4・縁高 0.22・穴リング r0.26〜0.42 に 3 穴×28°／Sieve_Dish_U: φ0.9・2 穴×40°。桟は屋根形 0.02: 静止した球が皿と一緒に回り続けない）
 ╲______╱  Dish 1     層ごとに回転方向を交互（±8rpm）、穴の位相は 37° ずつずらす
   ...               層間隔 0.34（L）／0.32（U）。透明筒（皿の縁との隙間 0.03 ＜ d/2）
 ╲______╱  Dish 14
   ╲____╱  Funnel（喉 2.4d）→ Exit トリガー（到達 = 抽選）→ Gate（抽選が終わったら閉じる）→ 8° 下りシュート → 結果レール
```

- 下段は原点、上段は x=−1.7。両方とも結果レール（z=−1.10・+X 側 3° 下り）へ落とし、7 球が到達順に並ぶ。
- `SieveMachine.DrawNext` は受け口に着いた順のキューから 1 球ずつ返す（抽選の合間に着いた球も落とさない）。

### 3.2 別ボールの縦連クルーン塔 ×7（`KuruunTower`。ロトマシーンを中心とする半径 6.2 の半円弧に扇状配置・正面を機械に向ける）

並び（弧の左→右）: 1(x1)・0(x3)・64(x6)・**33(x11)**・2(x10)・81(x4)・10(x1)。

```
   ↓ 投入（最上段: コーン面 r=0.85・角度 135° の 0.59 上から静止落下 = 下段の喉からの落差と同じ。MC の entryHeight と一致させる）
 ┌──────────┐  Kuruun_Bowl（回転 10rpm）: 縁 r1.0・壁高 0.56・コーン 27°（r1.0,h0.28 → r0.65,h0）・穴リング r0.45〜0.65 に 6 穴×36°（桟は屋根形 0.012: 止まった球が穴へ転がる）・中央ドーム h0.22
  ╲   ○   ╱   球はコーンを螺旋で下り、穴からコレクタへ落ちる（落下角は回転で一様化）
   ╲_____╱
  ┌‾‾‾‾‾‾‾‾┐  Kuruun_Collector_<variant>（静止）: 天端 −0.20。当たり扇形 = 内側へ 23° 下り → 内縁 r0.36 から中央へ落下 → Win トリガー（−0.44）→ 漏斗（喉 2.4d・−0.70）→ 次段のコーン面（x を ±0.425 交互にずらす）
  │  樋   │   ハズレ扇形 = 外側へ下り（内縁の縁 rim_h 0.12 で当たり側へ越えない）→ 樋（r0.74〜0.94・幅 2d・出口へ 0.35/半周の勾配）→ 正面の出口（開口 20°）→ 真っ直ぐ 6° 下りのシュート → 幅 1.2 の落下チャンネル（前板 Slick で真下へ）→ ハズレトレイ（Slick・反発 0）
```

- 段間隔 1.45（喉 −0.70 → 次段コーン面 −1.29。落差 0.59 = MC の `entryHeight`）。11 段で約 16 m。1.25 だと下段の縁が上段の樋を突き抜けて球が止まる（AGENTS.md 罠19）。最下段を当たりで抜けた球は喉の真下の完走トレイへ。
- 当たり扇形の境界角はメッシュの等分（3.75°）に丸めず、そのままの角度で切る（`gen_kuruun.py`）。校正の結果は本書 2.1 節。
- 球の減衰は **素の物理**（角 0.05・線 0。MC と同じ）。漏斗内だけ角減衰 2.0（喉で周回し続けない。当たり外れ確定後なので確率に影響しない）。
- 詰まったら（25s）その段の投入点へ戻してやり直す。**喉へ置いて当たりを作ることは絶対にしない**。

### 3.3 進行（`LotoDirector`）

1. 上段・下段の篩を回し、上段の到達 1 球 → 下段の到達 6 球（`pauseBetween` 1.5s）。終わったら Gate を閉じる。カメラは抽選中の篩の正面 1.9m（FOV 40）で、**高さは最下の球に追従**（`SieveMachine.Follow`。User 指示 2026-09-03: 篩の抽選はアップで見せる）。
2. 別ボール 1 → 10 → 0 → 2 → 33 → 64 → 81 の順に塔へ（カメラは球に追従・FOV 40）。
3. `Cam_Overview` に切り替え、JSON を書く。`-quit` 指定なら 3 秒後に終了。

起動引数: `-seed N`（未指定は時刻）／`-out path`（既定 `result.json`）／`-speed x`（`Time.timeScale`）／`-quit`。

### 3.4 球のスキンと創作DB

- `Assets/Data/BallSkins.asset`（`BallSkinTable`）: 全 106 球（ロト 1〜99 ＝ `Drum`、別ボール 7 ＝ `Streak`）の 1 行ずつ。行 = テクスチャ・tint・創作DB の `db`/`dbNum`。`Build Loto Scene` が足りない行だけ足す（既存行の手貼りは保持）。テクスチャが空の行は `defaultTexture`（いまは LotteryBallKit の `BallSkins_Sample`＝仮）。正式なテクスチャは User が Inspector で 1 球ずつ差し替える。
- 別ボールのキャラ対応（User 指定 2026-09-03。`BallSkinTable.StreakOverrides`）: 0→`000`(チトセ)／10→`10-alt`(ディケ)／2→`2-alt`(バイナ)／33→SemiPrimary `3x11`(トレッド)／64→SemiPrimary `64-sxp`(ゼフィア)／81→SemiPrimary `9x9`(クック。Progress notProceeded のため公開まで名前は空)。1 とロトの球は Primary の同番号（2→2(ツグ)、10→10(ミツル)）。
